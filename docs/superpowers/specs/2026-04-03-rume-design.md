# Vela Phase 3: RUME (Remove Unused Module Elements) — Design Spec

## Overview

Phase 3 adds RUME: removal of unused tables, memories, globals, and imports from core modules. Builds on the Phase 2 index renumbering infrastructure, extending it from function-only to all index spaces. Includes deletion of unused imports, which may require component metadata awareness (to be validated during implementation).

## Background

Phase 2 achieved 8.6-9.7% reduction via DCE + DFE. RUME targets additional unused elements: tables, memories, and globals that are no longer referenced after function elimination. The wite investigation showed 96KB reduction from RUME on AWSCC, but with Phase 2 now deleting significantly more functions, more elements may become unreferenced.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Scope | Table + Memory + Global removal | Type removal deferred (complex, unclear benefit) |
| Import handling | Delete unused imports (all kinds) | Maximum reduction; 138 imports on AWSCC/AWS |
| Component metadata | Assume name-based references don't break; validate with wasmtime | Component Model instantiate and canon lift use names, not indices |
| Renumberer | Extend `FunctionRenumberer` to `ModuleRenumberer` with all index spaces | One struct, one rebuild pass for all deletions |
| Approach | Usage analysis → Renumberer extension → rebuild extension → validate | Incremental, testable at each step |

## Usage Analysis

### `analyze_usage`

```rust
pub struct UsageInfo {
    pub used_tables: HashSet<u32>,
    pub used_memories: HashSet<u32>,
    pub used_globals: HashSet<u32>,
}

pub fn analyze_usage(module_bytes: &[u8]) -> Result<UsageInfo, VelaError>
```

Scans the module to determine which tables, memories, and globals are actually used.

**Sources of usage:**

Instructions in function bodies:
- Table: `table.get`, `table.set`, `table.grow`, `table.size`, `call_indirect`, `table.fill`, `table.copy`, `table.init`
- Memory: `*.load`, `*.store`, `memory.size`, `memory.grow`, `memory.fill`, `memory.copy`, `memory.init`
- Global: `global.get`, `global.set`

Section-level references:
- Export section: exported tables/memories/globals are used
- Element section: referenced table index is used
- Data section: referenced memory index (for active data segments) is used
- Global section: `global.get` in initialization expressions

**Important:** Analysis runs on the original module bytes (before any function deletion). The `reachable` function set from DCE is used to skip scanning dead function bodies — only instructions in reachable functions contribute to usage.

## ModuleRenumberer

Extends the Phase 2 `FunctionRenumberer` to handle all index spaces:

```rust
pub struct ModuleRenumberer {
    pub function_map: Vec<u32>,
    pub table_map: Vec<u32>,
    pub memory_map: Vec<u32>,
    pub global_map: Vec<u32>,
}

impl Reencode for ModuleRenumberer {
    type Error = Infallible;

    fn function_index(&mut self, func: u32) -> Result<u32, Error<Self::Error>> {
        Ok(self.function_map[func as usize])
    }
    fn table_index(&mut self, table: u32) -> Result<u32, Error<Self::Error>> {
        Ok(self.table_map[table as usize])
    }
    fn memory_index(&mut self, memory: u32) -> Result<u32, Error<Self::Error>> {
        Ok(self.memory_map[memory as usize])
    }
    fn global_index(&mut self, global: u32) -> Result<u32, Error<Self::Error>> {
        Ok(self.global_map[global as usize])
    }
}
```

Each index map is generated by `build_index_map(count, &HashMap::new(), &removals)` (no redirects for table/memory/global — only removals).

## rebuild_module Extension

`rebuild_module` is extended to skip removed elements in additional sections:

- **Import section**: Skip import entries for removed functions, tables, memories, and globals. This requires tracking which imports correspond to which index space.
- **Table section**: Skip entries for removed (non-import) tables.
- **Memory section**: Skip entries for removed (non-import) memories.
- **Global section**: Skip entries for removed (non-import) globals.
- **Element section**: Remains handled by `ModuleRenumberer` (table indices auto-rewritten).
- **Data section**: Remains handled by `ModuleRenumberer` (memory indices auto-rewritten).

### Import Section Handling

The import section contains all imports in order: functions, tables, memories, globals. Each import occupies an index in its respective index space. When removing an unused import, we skip it in the import section and the corresponding index is accounted for in the removal set.

To determine which imports to skip, `rebuild_module` needs a combined removal set that includes import indices. The import's index space is determined by its `TypeRef` variant (Func, Table, Memory, Global).

## Component Metadata Validation Strategy

Component Model's `(instantiate ...)` and `(canon lift ...)` use string names to reference core module imports/exports. This means core module internal index changes should not break component-level wiring.

**Validation approach:**
1. Implement RUME with import deletion
2. Test with wasmtime on Component WASM (integration tests)
3. If wasmtime instantiation fails, add component metadata rewriting
4. If it succeeds, no component metadata changes needed

This is validated during implementation, not assumed correct.

## Test Strategy

| Layer | Content |
|-------|---------|
| `rume.rs` unit | `analyze_usage` correctly detects used/unused tables, memories, globals |
| RUME integration | Unused global removed, module valid, global count decreases |
| RUME + import | Unused import removed, module valid, import count decreases |
| Combined DCE+DFE+RUME | All passes active, wasmtime executes correctly |
| Component WASM | Optimized Component WASM runs in wasmtime (validates component metadata intact) |

## Success Criteria

| Metric | Criterion |
|--------|-----------|
| Correctness | Optimized WASM runs correctly in wasmtime |
| Additional reduction | Measurable reduction beyond Phase 2 on AWSCC/AWS |
| Speed | 8.3MB WASM optimized within 1 minute |
| Validity | `wasmparser::Validator` passes |
| Component compatibility | Verified with wasmtime; component metadata rewriting added if needed |
